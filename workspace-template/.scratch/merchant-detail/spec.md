# 商家详情查看功能 Spec

**Status:** ready-for-agent

## Problem Statement

产品已有商家列表、Merchant 模型和商家详情查询接口，但用户无法从列表进入一个稳定、可读的商家详情视图。普通成员需要查看其授权范围内商家的基础资料和经营状态，管理员需要查看全部商家。缺少明确的授权边界、字段范围和异常反馈，可能导致越权访问、敏感联系方式泄露或无法恢复的加载失败。

## Solution

在现有商家列表中提供详情入口，点击某行后以该行商家的稳定唯一 ID 打开独立详情页，并复用现有详情查询接口。管理员可查看全部商家，普通成员只能查看权限系统授予范围内的商家。详情页为只读，展示基础资料、营业/账号状态、联系方式以及创建/更新时间；对空字段、加载中、无权限、商家不存在和服务异常提供明确状态与恢复操作。

本期不新增商家数据源、Merchant 模型或权限体系，服务端必须在每次详情请求中执行现有授权规则。

## User Stories

1. As an 普通成员, I want 从商家列表进入授权范围内的商家详情, so that 我可以核对商家资料和当前状态。
2. As an 普通成员, I want 无权访问的商家不会返回任何详情字段, so that 商家信息不会被越权获取。
3. As an 管理员, I want 从商家列表进入任意商家详情, so that 我可以处理商家运营和支持问题。
4. As an 用户, I want 在详情页看到商家 ID 和名称等基础资料, so that 我可以准确识别目标商家。
5. As an 用户, I want 在详情页看到商家的营业或账号状态, so that 我可以判断商家当前是否正常。
6. As an 用户, I want 在详情页看到已有联系方式, so that 我可以联系或核对商家。
7. As an 用户, I want 看到创建时间和更新时间, so that 我可以了解资料的新鲜程度。
8. As an 用户, I want 缺失字段显示统一占位, so that 单个数据缺失不会被误认为页面故障。
9. As an 用户, I want 详情加载中有明确反馈, so that 我知道系统正在请求数据。
10. As an 无权限用户, I want 看到明确的拒绝提示且不泄露商家是否包含敏感信息, so that 我能理解访问边界。
11. As an 用户, I want 商家不存在时得到明确提示, so that 我不会把数据删除误判为网络故障。
12. As an 用户, I want 服务失败后可以重试或返回列表, so that 我能恢复浏览流程。
13. As an 用户, I want 返回商家列表时保留原有浏览上下文, so that 我能继续之前的筛选和浏览位置。
14. As an 安全负责人, I want 详情接口复用现有授权和脱敏策略, so that 新页面不会扩大信息暴露范围。
15. As an 产品维护者, I want 详情采用独立页面, so that 后续可以扩展商家信息而不改变列表主流程。

## Implementation Decisions

- 首期唯一入口为现有商家列表；点击商家行携带稳定、不可变的商家 ID，不使用名称作为查询主键。
- 详情采用独立页面，沿用宿主产品路由、导航、视觉和错误处理规范。
- 详情为只读视图，不提供编辑资料、启用/停用、删除、负责人变更、导出或其他写操作。
- 复用现有 Merchant 模型和详情查询接口，不新增冗余详情模型、独立缓存数据源或第二套字段定义。
- 展示范围包括：商家 ID、名称、Logo/头像（若模型已有）、已有基础资料、营业/账号状态、已有联系方式，以及创建时间和更新时间。
- 联系方式和其他可能敏感的字段必须遵循宿主已有脱敏与可见性规则；本功能不得新增明文暴露。
- 字段为 `null`、空字符串或接口缺失时显示“暂无”，单个字段缺失不阻断其他可用数据展示。
- 营业/账号状态直接使用接口返回的状态枚举及现有文案，前端不自行推断或改写状态。
- 时间统一使用 `YYYY-MM-DD HH:mm` 格式和宿主默认时区。
- 管理员身份和普通成员授权范围复用现有登录态、角色及授权关系；管理员可读取全部商家，普通成员仅可读取授权范围内商家。
- 每次详情请求均由服务端鉴权。无权限返回 403 或宿主等价错误，响应不得包含目标商家字段；不存在返回 404 或宿主等价错误。
- 加载期间不显示上一次商家的残留数据；通用网络/服务错误展示失败提示，并提供重试和返回列表操作。
- 返回列表时保留宿主列表已有的筛选、分页和滚动位置能力。
- 不要求数据库或 schema 变更；若现有接口未返回已存在于 Merchant 模型的约定字段，只扩展现有接口契约，不另建数据源。

## Testing Decisions

- 采用最高可用的外部行为缝：以“登录身份 + 商家 ID → 最终详情页状态”为主，贯通服务端授权、查询响应和页面结果，不测试内部函数调用顺序。
- 普通成员主路径验证授权范围内商家可进入独立详情页，并断言全部约定字段、状态和时间展示。
- 权限路径验证管理员可访问任意商家，普通成员访问授权范围外商家被拒绝，直接篡改商家 ID 也不能绕过服务端鉴权。
- 状态路径验证加载中、空字段、商家不存在、通用错误、重试和返回列表上下文。
- 重点断言无权限响应不包含目标商家数据，且页面不会显示残留或半份详情。
- 优先复用宿主现有的授权接口测试、页面导航测试和端到端测试模式；具体测试工具由实现者按宿主项目确认。

## Out of Scope

- 新建或重做商家列表、搜索、筛选、分页、排序和列表字段。
- 商家资料编辑、创建、删除、合并、状态变更、负责人变更或导出。
- 经营数据、交易/订单、结算、活动、跟进记录、操作历史和审计日志。
- 新建 Merchant 模型、替换存储系统、独立详情数据源或新的角色权限管理界面。
- 为管理员建立独立白名单；管理员身份沿用宿主现有角色体系。

## Further Notes

- 本 Spec 假设宿主已经具备商家列表、Merchant 模型、详情查询接口、登录态、管理员角色、普通成员授权范围和字段脱敏策略。
- 当前产品工作区不包含宿主业务代码；具体路由、接口名称、字段标识和授权关系字段由实现者接入时确认，但不得改变本 Spec 的外部行为和权限边界。
- 若宿主缺少详情接口或无法可靠判断授权范围，应先报告依赖缺口，不得由详情页面临时发明替代权限机制。
